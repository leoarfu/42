MOBILE-04

The 3GPP NTN Standard, Plainly

The full derivation — HARQ duty-factor arithmetic, the OFDM resource grid, K_offset scheduling, and a working throughput engine — lives in M5-5[cite: 1, 2, 3]. This page explains what changes and why, in plain terms, before that page's notation[cite: 1, 2, 3].

1. Why 5G needed a satellite patch at all

Terrestrial 5G New Radio (NR) was designed assuming cell radii of a few kilometres, round-trip times (RTT) under 1 millisecond, and a smartphone (User Equipment, or UE) that barely moves relative to its cell tower[cite: 1, 2, 3]. A LEO satellite link breaks all three assumptions at once: the "cell" is a spot beam originating 550 to 1,200 km away, the round trip spans tens of milliseconds, and the satellite streaks across the sky at 7.6 km/s[cite: 1, 2, 3].

None of the terrestrial standard's timing or mobility logic survives that unmodified — which is why 3GPP Release 17 formally introduced Non-Terrestrial Networks (NTN) as a distinct radio access extension[cite: 1, 2, 3].

2. Deep Dive: What is HARQ?

Before examining how 3GPP patched 5G for space, we must define HARQ (Hybrid Automatic Repeat Request)[cite: 1, 2, 3]. It is one of the most critical MAC/Physical layer mechanisms in cellular communications[cite: 1, 2, 3].

Automatic Repeat Request (ARQ) vs. Hybrid ARQ

  • Standard ARQ: When a receiver detects corrupted data, it discards the bad packet entirely and requests a total retransmission.
  • Hybrid ARQ (HARQ): When a receiver gets a corrupted packet, it does not discard it. Instead, it stores the corrupted soft bits in a memory buffer. When the retransmission arrives, the receiver mathematically combines the old corrupted data with the new retransmission to successfully decode the message.

The Feedback Loop: ACK / NACK

Every time the base station transmits a packet, it waits for an acknowledgment from the receiver[cite: 1, 2, 3]:

  • ACK (Positive Acknowledgment): "I received the packet cleanly. Send the next one."[cite: 1, 2, 3]
  • NACK (Negative Acknowledgment): "The packet was corrupted. Store it in my HARQ buffer and retransmit."[cite: 1, 2, 3]

HARQ Processes and the Stop-and-Wait Problem

To avoid stopping the entire transmission while waiting for an ACK/NACK, LTE and 5G use multiple parallel HARQ processes. Think of them as separate, numbered stop-and-wait threads running simultaneously[cite: 1, 2, 3].

Terrestrial 5G allocates up to 16 HARQ processes. In a terrestrial network with a 1 ms RTT, 16 processes are more than enough to keep the pipe 100% full at all times[cite: 1, 2, 3].

Why Satellite LEO RTT Breaks Terrestrial HARQ

At LEO distances (550 km altitude + slant paths), the round-trip propagation delay increases from <1 ms to 25–50 ms[cite: 1, 2, 3].

If you only have 16 HARQ processes, the transmitter fires off 16 subframes in 16 milliseconds. Then, it runs out of processes! It must pause completely and sit idle for the remaining ~30 milliseconds until the first ACK arrives back from space. This empty waiting period causes the link capacity to stall, drastically degrading throughput[cite: 1, 2, 3].

3. The Four 3GPP Release 17 NTN Fixes

3.1 Timing — Split Compensation

A terrestrial gNB tells a nearby phone exactly how much to adjust its transmit timing via Timing Advance (TA). At satellite range, propagation delay is huge and changes rapidly due to satellite motion. NTN splits this task[cite: 1, 2, 3]:

  • Common TA: The satellite/network broadcasts a baseline timing correction common to the entire beam[cite: 1, 2, 3].
  • UE Specific TA: The phone computes its own specific distance to the satellite using its built-in GPS/GNSS receiver and the satellite's orbital ephemeris, adjusting its uplink timing automatically[cite: 1, 2, 3].

Legacy Handsets vs. Rel-17 NTN Handsets: Unmodified smartphones (like those served by Starlink D2D today) lack Rel-17 NTN software and cannot calculate their own UE-specific TA[cite: 1, 2, 3]. Therefore, the network must do 100% of the compensation by keeping spot beams extremely narrow so that timing variance across users in a single beam stays within legacy cell-tower tolerances[cite: 1, 2, 3].

3.2 Doppler — Split Frequency Compensation

Satellite velocity produces up to ±48 kHz of Doppler shift[cite: 1, 2, 3]. Standard 5G devices cannot lock onto subcarriers with shifts this large. NTN splits frequency compensation using the same pattern: the satellite/feeder link pre-compensates for the orbital shift at the center of the beam, while Rel-17 handsets calculate their residual offset locally using GNSS data[cite: 1, 2, 3].

3.3 HARQ Adaptations — Expanding or Disabling Feedback

To resolve the LEO HARQ throughput stall explained in Section 2, 3GPP Release 17 introduced two options[cite: 1, 2, 3]:

  1. Expanding Processes: Rel-17 expands the maximum number of parallel HARQ processes from 16 up to 32 processes, filling more of the satellite delay pipe[cite: 1, 2, 3].
  2. Disabling HARQ Feedback: For satellite links where 32 processes are still insufficient (or buffer memory on the UE is constrained), 3GPP permits disabling HARQ feedback entirely at the MAC layer[cite: 1, 2, 3]. The network transmits continuously without waiting for ACKs/NACKs, relying on upper layers (like RLC or TCP) for error recovery[cite: 1, 2, 3].

3.4 Scheduling — $K_{\text{offset}}$ Timing Offsets

In terrestrial 5G, the scheduler assumes a control command (such as an uplink grant) takes effect almost instantly (e.g., $K_2$ slots later). Over a satellite link, the command takes 25+ ms just to travel to the phone[cite: 1, 2, 3].

NTN introduces an explicit delay offset parameter called $K_{\text{offset}}$ into MAC and RRC messages[cite: 1, 2, 3]. $K_{\text{offset}}$ tells the phone's scheduler: "Add $K_{\text{offset}}$ milliseconds to all standard timing relationships to account for physical space delay before executing this grant."[cite: 1, 2, 3]

4. Protocol Stack Impact

All four 3GPP NTN fixes operate exclusively at the lower layers[cite: 1, 2, 3]:

LayerImpact in 3GPP Rel-17 NTN
PHY (Physical)Doppler pre-compensation, GNSS-assisted timing advance[cite: 1, 2, 3]
MACHARQ disable/expansion (up to 32 processes), $K_{\text{offset}}$ timing shifts[cite: 1, 2, 3]
RLC / PDCPUnchanged protocol logic; configured with larger reordering buffers[cite: 1, 2, 3]
NAS / CoreUnchanged; treats the satellite link as standard 5G Radio Access Network (RAN)[cite: 1, 2, 3]

5. Transparent vs. Regenerative NTN Architecture

The standard categorizes satellite payloads into two architectural modes[cite: 1, 2, 3]:

  • Transparent (Bent-Pipe): The satellite acts as an RF repeater. It receives the signal, shifts frequency, amplifies it, and bounces it to a ground gateway gNB[cite: 1, 2, 3].
  • Regenerative (On-Board Processing): The satellite carries a full or partial 5G gNB base station on orbit, demodulating and decoding packets directly in space[cite: 1, 2, 3].

6. Where Starlink Mobile Sits vs. 2027 Convergence

Starlink Mobile's current Direct-to-Cell deployment uses a proprietary implementation of unmodified LTE (4G), not 3GPP 5G NR-NTN[cite: 1, 2, 3]. It tricks standard phones into seeing a normal terrestrial tower while handling extreme Doppler/delay compensation entirely on the satellite payload[cite: 1, 2, 3].

Reported industry roadmaps point toward a 2027 convergence point, where Starlink Gen2 D2D payloads and European constellations (like IRIS²) transition to standardized 3GPP Rel-17/18 5G NR-NTN waveforms, enabling native standard compatibility across all commercial handsets[cite: 1, 2, 3].
